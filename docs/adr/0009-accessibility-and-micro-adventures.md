# ADR 0009: Условия доступности и добровольное микроприключение

Дата: 2026-10-20  
Статус: принято

## Контекст

Для части людей исходный выбор мест бесполезен без сведений о доступности и длине переходов. При этом OSM чаще не сообщает доступность, а его отметка места не описывает весь путь от точки старта. Игровой сценарий может сделать прогулку интереснее, если не подменяет точность рекомендаций и не требует отслеживать пользователя.

## Решение

- Добавить добровольное условие «Нужен доступ для коляски». Сервер допускает в городской результат только места с явным `wheelchair=yes` в исходной записи OSM. `limited`, `no` и отсутствующее значение не считаются подтверждением и исключаются при включённом условии. Поиск может точечно дополнить снимок OSM через Overpass; пустой результат лучше выдуманного доступного места.
- Показывать отметку как **сведения сообщества OSM о месте**, со ссылкой на запись. Не называть маршрут доступным или проверенным: вход, пандус, подъёмник, туалет, покрытие и бордюры могут отличаться от данных или вообще не быть описаны. Ссылка на [карту доступности Казахстана](https://inva.gov.kz/ru#map-box) помогает провести отдельную проверку; приложение не интегрирует её данные и не связывает записи автоматически.
- Для загородного каталога пока нет сопоставимых сведений о доступности. Строгое условие не подбирает такие поездки и прямо объясняет, почему результат пуст. Будущее подтверждение поездки потребует данных о точке назначения, дороге и услугах, а не только OSM тега места.
- Добавить добровольное условие коротких переходов только для городской **пешей** прогулки. Сервер оценивает от старта до первой остановки и между остановками примерно по 10 минут максимум на каждый переход. Это геометрическая оценка; реальное время, тротуары, уклоны и барьеры не проверены. Для транспорта и загородной поездки условие не применяется, а интерфейс сообщает об этом.
- Добавить добровольное условие «Без спешки» только для городского маршрута. Сервер ограничивает его двумя остановками и отводит больше времени на каждую в пределах выбранной длительности. Оно не подтверждает наличие места для отдыха, туалета или спокойной атмосферы: для таких свойств нужен отдельный источник.
- Добавить добровольный сценарий «Микроприключение» для городской прогулки: по возможности выбрать 2–3 разные реальные остановки, затем предложить у каждой короткое задание с низкой нагрузкой. Примеры должны подходить разным людям: заметить звук, настроение или деталь, сравнить две точки, выбрать любимую. Задание помечено как **идея приложения**, не как факт о месте. Желание пользователя и ограничения важнее числа остановок или разнообразия; при малом числе подходящих POI показывать только реальные доступные остановки.
- Отметки выполнения заданий держать в памяти открытой Mini App и сбрасывать при новом результате. Не требовать GPS подтверждения, фотографий, публикации или профиля. Все новые элементы и сообщения должны быть на выбранном языке (RU/KK/EN), доступны кнопками и клавиатурой без обязательного перетаскивания.

## Следствия и проверка

Фильтр повысит точность заявлений, но сократит выдачу. На момент решения у небольшого числа мест в городском снимке есть `wheelchair=yes`; неизвестное нельзя считать недоступным, но и нельзя обещать доступность. Следующий этап — проверяемая маршрутизация по тротуарам с данными о покрытии, уклонах и бордюрах. Пока линия между точками остаётся схемой в смысле ADR 0008.

Для демо и регрессии нужны сценарии: `yes` допускается, `limited`/`no`/отсутствие отметки отсекаются; загородная поездка со строгим условием даёт понятный пустой результат; каждый короткий переход укладывается в приблизительный предел; «Без спешки» даёт не более двух остановок и укладывается в выбранное время; игровые задания не появляются в загородном режиме и не сохраняют координаты. Основание для значения тега — [OSM Key:wheelchair](https://wiki.openstreetmap.org/wiki/Key:wheelchair); проблемы маршрутизации для коляски отдельно описаны в [OSM Rollstuhlrouting](https://wiki.openstreetmap.org/wiki/Rollstuhlrouting). Управление следует требованиям [WCAG 2.2 для альтернатив перетаскиванию](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/).
