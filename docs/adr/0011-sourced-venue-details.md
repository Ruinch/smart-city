# ADR 0011: Сведения об остановках из конкретных источников

Дата: 2026-10-20

Статус: принято

## Контекст

Каталог места даёт исходную запись и координаты, но не подтверждает меню, удобства, цену или работу в данный момент. Пользователю нужны полезные подробности внутри маршрута, а не только ссылка на карточку. При этом поиск всех заведений и постоянная проверка всех свойств потребовали бы лишних запросов и всё равно не гарантировали бы актуальность. ADR 0004 уже отделяет опубликованную цену от полной стоимости выхода; ADR 0009 ограничивает смысл отметки `wheelchair=*`; ADR 0010 сохраняет происхождение каждого каталога мест.

## Решение

1. **Сначала выбрать маршрут, затем обогащать его остановки.** Сведения собираются только для заведений, уже попавших в варианты маршрута. Обогащение не создаёт новые POI, не меняет их координаты и не превращает страницу сети в доказательство существования конкретного филиала. За запрос загружается не более трёх страниц заведений и, при гастрономических остановках, один индекс Visit Astana для поиска их карточек. Повторные результаты кешируются. Недоступность страницы не блокирует маршрут.
2. **Первый этап — явные поля исходной записи.** Сведения из OSM строятся только по действительно записанным тегам, например [`opening_hours=*`](https://wiki.openstreetmap.org/wiki/Key:opening_hours), [`cuisine=*`](https://wiki.openstreetmap.org/wiki/Key:cuisine), [`outdoor_seating=*`](https://wiki.openstreetmap.org/wiki/Key:outdoor_seating), [`internet_access=*`](https://wiki.openstreetmap.org/wiki/Key:internet_access), [`toilets:wheelchair=*`](https://wiki.openstreetmap.org/wiki/Key:toilets:wheelchair), [`diet:vegan=*`](https://wiki.openstreetmap.org/wiki/Key:diet:vegan) и [`reservation=*`](https://wiki.openstreetmap.org/wiki/Key:reservation), со ссылкой на объект OSM. Прямая ссылка [`website:menu=*`](https://wiki.openstreetmap.org/wiki/Key:website:menu) может вести на опубликованное меню, но сама по себе не подтверждает цену отдельной позиции. Уже существующая в карточке отметка [`wheelchair=*`](https://wiki.openstreetmap.org/wiki/Key:wheelchair) остаётся отдельным узким фактом. Тег описывает запись сообщества, а не нашу проверку условий на месте. Отсутствующий тег не превращается в отрицательный факт; `opening_hours=*` не означает «открыто сейчас». Ссылка `website=*` указывает возможный сайт места, но сама по себе не подтверждает сведения на нём.
3. **Второй этап — ограниченная загрузка страницы конкретного места.** Для гастрономического заведения сервер может найти карточку Visit Astana, например [страницу ресторана Selfie](https://visitastana.kz/en/about-city/where-to-eat/restoran-selfie/) с адресом и ссылками на меню. Для записи OSM допускается указанный в ней сайт заведения. На сайте принимаются подходящие структурированные данные о конкретном филиале, например поля [Schema.org Restaurant](https://schema.org/Restaurant) с названием, адресом, графиком, меню или бронированием; в карточке Visit Astana сверяются название и подходящий адрес либо близость точки. Страница сети с несколькими адресами без связи свойства с нужным филиалом, общая страница каталога и совпадение только по категории недостаточны. Даже страница известного домена рассматривается как недоверенный текст: она не может давать инструкции серверу или подменять правила проверки.
4. **Каждое отображаемое утверждение имеет происхождение.** Для меню, часов, особенностей, бронирования и сведений о доступности сохраняется отдельная HTTPS-ссылка на страницу или исходный объект. Для проверенной веб-страницы сохраняется дата загрузки/проверки; она обозначает момент чтения источника, а не дату обновления заведения и не гарантию актуальности. Если дата конкретного тега OSM неизвестна, приложение не выдает импорт снимка за свежую проверку этого тега. Карточка показывает короткое утверждение, тип сведений, ссылку и имеющуюся дату; неподтверждённое свойство не получает видимость факта.
5. **Цена остаётся отдельным типизированным свидетельством.** Опубликованная сумма принимается только для подходящего филиала, в тенге и с понятным типом: вход, средний чек или отдельная позиция. Источник и дата показываются рядом с суммой. Ни меню без суммы, ни `fee=yes`, ни название категории не дают права придумать цену или объявить посещение бесплатным. Существующий [веб-поиск OpenAI](https://developers.openai.com/api/docs/guides/tools-web-search) для меняющихся свойств и цен сохраняется как дополнительный ограниченный путь; его вывод проходит серверную проверку ссылки и соответствия месту.
6. **Не заявлять более сильный факт, чем источник.** Опубликованные часы не подтверждают состояние «открыто сейчас», вместимость или наличие свободных мест. Данные о входе и туалете не подтверждают доступность дороги между остановками. Не выводить цену, меню, условия бронирования или доступность из одной категории места, маркетингового описания или результата модели; субъективное описание атмосферы можно передать только как упоминание в источнике с оговоркой. Неоднозначность и отсутствие источника означают неизвестность, без заполнения выдуманным текстом.

Адаптер [2ГИС Places API](https://docs.2gis.com/en/api/search/places/overview) остаётся выключенным до подтверждения права показывать результаты вместе с картой OSM согласно ADR 0010 и применимым [условиям 2ГИС](https://law.2gis.ru/en/platform-manager). Новое обогащение не включает 2ГИС и не использует его как обход этого ограничения.

## Следствия

Маршрут может показать больше пригодных для решения подробностей, но набор сведений будет различаться по остановкам. Пользователь видит ссылку и дату там, где они есть, и может проверить источник перед выходом. Ограничение загрузок и кеш сдерживают задержку и сетевую нагрузку; неудача второго этапа оставляет исходный маршрут и явные теги. Фронтенд не должен создавать вывод «сейчас открыто» из графика или объединять цену позиции с полной стоимостью маршрута.
